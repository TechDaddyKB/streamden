# Contributing to StreamDen

Read [AGENTS.md](AGENTS.md) and the [board workflow](docs/agents/board.md).
Work on one dispatched, ready card in your own worktree and stay within its Scope paths.
The app workspace is reserved for DEN-19; this root package currently contains development tooling only.

## Licensing and clean-room contributions

Application code is **GPL-3.0-or-later**. SDKs, protocol schemas and plugin templates are
**MIT OR Apache-2.0** (D-016). Dependencies must be compatible with the applicable license.
External contributors must certify the [Developer Certificate of Origin](https://developercertificate.org/)
using `git commit -s` (a `Signed-off-by:` trailer). Owner and fleet-agent contributions do not require
DCO sign-off. A later PR check will enforce external-contributor sign-offs; the local hook does not.
There is no CLA.

Use public documentation, observed behavior and data formats for interoperability. Never copy code
from Streamer.bot, SAMMI, Speaker.bot or GPL projects such as Firebot and Social Stream Ninja.
Do not commit secrets; use fixtures and mocks where credentials are unavailable.

## Install and run hooks

Use Node.js 22.12 or newer and pnpm 12.14.0. From the repository root:

```sh
pnpm install --lockfile=false --ignore-scripts
node_modules/.bin/lefthook install
node_modules/.bin/lefthook run pre-commit
node_modules/.bin/lefthook run pre-commit --force
node_modules/.bin/lefthook run commit-msg -- /absolute/path/to/sample-message.txt
node scripts/check-branch-name.test.cjs
```

Dependencies are pinned in `package.json`. Each linked worktree needs its own dependency install.
Without a root lockfile, the install resolves transitive dependencies anew. Once the generated root
lockfile is checked in, use `pnpm install --frozen-lockfile --ignore-scripts` in each worktree instead.
Plain `pnpm exec` can auto-install dependencies and create a lockfile with pnpm 12.
`pnpm --config.verifyDepsBeforeRun=false exec lefthook …` skips dependency verification, but
package-manager setup can still write a lockfile. The commands above and the commit hook invoke
installed binaries directly, avoiding both side effects.
Hook installation is explicit and writes Git hooks shared by linked worktrees; coordinate installation
with other agents. Branches without Lefthook configuration are skipped. After merging, reinstall
from the main checkout before removing the installing worktree: generated hooks may reference its binary.
Running `lefthook run` verifies the config without installing hooks.
The commit-msg hook receives the message path from Git; pass it after `--` for manual verification.
Use `--force` to exercise pre-commit on a clean index (Lefthook otherwise skips it).
See the [Lefthook CLI](https://github.com/evilmartians/lefthook) and
[commitlint local plugins](https://commitlint.js.org/reference/plugins.html).

## Branches and commits

Branches must match `agent/(claude|codex|grok|other)/DEN-<digits>-<lowercase-slug>`,
`owner/<name>`, or `main`. During a rebase, hooks use the original branch from Git's rebase state;
other detached HEADs are rejected. Check an explicit name without switching:
`node scripts/check-branch-name.cjs agent/codex/DEN-12-repo-hygiene`.

D-037 requires a Conventional Commit subject, at most 100 characters, ending in `(DEN-n)`;
use `(planning)` or `(owner)` for non-card work. Follow it with a blank line and a body explaining
what changed, why and the checks actually run. Agent branches require exactly one
`AI-Assisted-By: Claude`, `Codex` or `Grok` in a final trailer block separated by a blank line:

```text
chore(repo): enforce contribution conventions (DEN-12)

Add shared hooks so all vendors follow the same commit policy.
Checks: branch validation and sample commit-message checks passed.

AI-Assisted-By: Codex
```

The trailer must match the branch vendor. `agent/other` must use one of the three supported
engine values because D-037 defines no fourth value. Owner/main commits may omit the AI trailer.
Human DCO trailers may share the final trailer block. AI co-author names, email addresses at
`anthropic.com`, `openai.com`, `x.ai` (including subdomains), and `Generated by/with` AI marker lines
are rejected; ordinary code-generation prose and human email domains are allowed.
Cleanup follows [Git's cleanup modes](https://git-scm.com/docs/git-commit#Documentation/git-commit.txt---cleanupmode)
and editor context: editor comments are stripped by default, while `-m`/`-F` preserve comment lines.
Custom comment characters and `core.commentChar=auto` are supported for editor templates.
Use `git -c commit.cleanup=<mode> commit` for explicit cleanup changes; Git does not expose the
`--cleanup` command-line override to hooks. Manual hook runs assume editor cleanup unless `GIT_EDITOR=:`.
Merge, revert and fixup messages receive the same checks; no default commitlint exemptions apply.

## Review and handoff

Use the PR template: link the card, paste Done-when output, name author and reviewer vendors,
and complete the cross-platform checklist. Review must come from another vendor; Grok work needs
Claude or Codex. Keep PRs to one card and roughly 400 changed lines or fewer. The owner merges.
Append the [handoff template (§B)](tasks/_TEMPLATE.md)
to the card detail and release with a short note. Advance only when every Done-when passes.
