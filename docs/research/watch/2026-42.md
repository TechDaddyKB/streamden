## Discord

**2026-10-14.** OAuth2 authorization responses that redirect to the app's `redirect_uri` now include `iss` set to `https://discord.com` (RFC 9207). Authorization-server metadata sets `authorization_response_iss_parameter_supported` to true. [official](https://docs.discord.com/developers/change-log) [official](https://docs.discord.com/developers/topics/oauth2#issuer-identification)

The code-grant redirect example is `?code=…&state=…&iss=https%3A%2F%2Fdiscord.com`. The implicit grant puts `iss` in the URI fragment. Docs say: if the app has more than one OAuth provider, check `iss` against Discord's issuer before exchanging the code. [official](https://docs.discord.com/developers/topics/oauth2#issuer-identification)

Pasting an incoming webhook URL does not use this redirect. The companion bot's OAuth redirect does. See DEN-28.

No other Discord changelog entry is dated inside the week. The previous one is 2026-10-06 (an Embedded App SDK rename), outside this window. [official](https://docs.discord.com/developers/change-log)

## Implications for StreamDen

1. YouTube Jewels gifts must be parsed as `snippet.giftDetails`. The March name `giftEventDetails` is the pre-rename docs. [official](https://developers.google.com/youtube/v3/live/revision_history) DEN-27 locks the child fields before Spec 05.
2. Discord OAuth redirects grew an `iss` parameter. A strict redirect parser that allows only `code` and `state` will drop or reject the login. Webhook URL paste is unaffected. [official](https://docs.discord.com/developers/topics/oauth2#issuer-identification) DEN-28.
3. OBS 33 is a CEF jump and drops Ubuntu 24.04 from the notes and the rc2 package list. S-2 should be re-run before 33 is the version we talk about. [official](https://github.com/obsproject/obs-studio/releases/tag/33.0.0-rc2) DEN-26. The reference box is Hyprland, not Ubuntu, so "24.04 removed" is a user-facing package fact, not a statement that StreamDen's own build broke.
4. Kick's official API did not change. [official](https://github.com/KickEngineering/KickDevDocs/commit/7f7afe7ace) A third-party app says unofficial chat hosts moved. [community](https://vtubepro.com/changelog) That supports staying on webhooks. DEN-29.
5. X Chat, Bluesky Spaces, and YouTube dual-stream are real, and none of them change the P1 Twitch + OBS slice. X Chat and Spaces both need a hosted receiver or on-device keys. [official](https://docs.x.com/xchat/introduction) [official](https://atproto.com/blog/devex-goals-for-spaces) Dual-stream is a second RTMP key in YouTube Studio, not a new Data API method this week. [official](https://docs.streamelements.com/selive/guides/youtube-dual-stream) [official](https://developers.google.com/youtube/v3/live/revision_history)
6. StreamElements' widget event surface did not gain keys in the 14 Oct docs drop. [official](https://github.com/StreamElements/docs/blob/0f3491bfe1/src/content/docs/overlays/widget-data.mdx)
