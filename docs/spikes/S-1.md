## 0. Correction: the first run was invalid

The first version of this report said that level 0 (no env vars, no quirk) "rendered correctly every time" and
that the early-GL quirk pushed rendering onto llvmpipe. The Codex review could not reproduce that: level 0 died
with `Error 71` on 3/3 launches. **The review was right. The first run measured a broken driver state.**

- At 21:05 the NVIDIA userspace was upgraded from 610.57.04 to 615.78.08, along with Mesa 26.2.5 and WebKitGTK
  2.54.1. The machine was **not rebooted**, so the 610 kernel module stayed loaded. The kernel log shows
  `NVRM: API mismatch` for NVIDIA clients from then on (e.g. quickshell, nvidia-smi) ([environment.txt](S-1/rerun/environment.txt)).
- The first run (22:07–22:43) therefore had **no working NVIDIA GL or EGL**. WebKit fell back to the AMD iGPU,
  and GTK to llvmpipe. That explains the `MESA-EGL … failed to create dri2 screen` lines and the "WebKit
  renders on the iGPU" finding. It also explains why NVIDIA's explicit-sync path, which causes `Error 71`,
  never ran.
- The machine was rebooted at 23:12. Since then, kernel module and userspace are both 615.78.08. The Codex
  review and this re-run both use that state, and they agree.
- The Codex review ran inside a sandbox. That did **not** cause its result: outside any sandbox, level 0 fails
  in the same way (§3).

Lesson for every later GPU spike: record `/proc/driver/nvidia/version` next to `nvidia-utils`, and check for
`API mismatch` in the kernel log first. Real users hit this state too, after an Arch upgrade without a reboot
(§4).

## TL;DR

**Conditional GO for Tauri 2. Out of the box, WebKitGTK is NOT reliable on Hyprland + NVIDIA.** Tauri 2 is
acceptable only if the graphics-compat ladder ships as a hard requirement, with an NVIDIA-aware default.

- **Level 0 (defaults) crashes on every launch: 0/11 painted at the reviewed HEAD, plus 0/4 in the variants
  below.** 330–365 ms after exec (once 598 ms; measured in `variants.jsonl`), GDK prints `Error 71 (Protocol error) dispatching to Wayland
  display.` and the process exits before first paint. A tiled launch and `GDK_SCALE=1` don't help.
- **NVIDIA's explicit sync triggers it.** Level 0 plus `__NV_DISABLE_EXPLICIT_SYNC=1` paints 6/6 and renders on
  NVIDIA.
- **Level 1 (the early-GL quirk) is the best configuration here.** It painted on all 13 launches (9 in the
  batches, 2 ladder starts, 2 probe runs) in about 350 ms. Everything renders
  on NVIDIA with no llvmpipe, and it uses 4.4 % CPU animated in a window, 12 % fullscreen at 5120×1440 and 0.4 %
  idle. This **reverses** the first report's "never enable the quirk" condition.
- Levels 2–3 (no DMA-BUF) paint 6/6 and 5/5, but WebKit paints on the CPU: 28 % fullscreen.
- **Level 4 (X11/XWayland) shows a blank window and never paints (0/7).** It fails with `Failed to create GBM
  buffer` and the process stays alive. X11 plus no-DMA-BUF paints 3/3.
- **The crash ladder rescues a clean install by itself.** The first start crashes at level 0, the second comes
  up at level 1, paints, and keeps level 1.
- Unchanged: tray, close-to-tray with recreate (the web-process fix still applies), the second window
  (`always_on_top` ignored, Hyprland `pin` works) and browser fallback.

GO conditions (§10): on Wayland with an NVIDIA GPU, start at the early-GL quirk; never ship level 0 as the
NVIDIA default; add a first-paint timeout so a blank-but-alive window also bumps the level; reorder the ladder
so plain X11 is not a step; keep the browser fallback.

## 2. What the spike contains

`spikes/S-1-tauri-shell/` holds a Vite + React + TS page (CSS animation plus an engine status panel), a chat
mock page, and a Rust backend:

- **Engine stand-in:** a Tokio task ticks once per second, emits `engine-tick` to webviews, sends it to
  browsers over SSE and appends to `engine.log`. It never depends on a window.
- **Shell:** the tray (Show / Hide to tray (destroy webview) / Second window (chat) / Open UI in browser /
  Quit) and close-to-tray. `ExitRequested` is prevented when the last window closes. Windows are recreated on
  demand, and the chat window asks for `always_on_top(true)`.
- **Local server** (axum, `127.0.0.1` only, Host and Origin guard): serves the same UI to a browser, plus
  `/api/state`, `/api/ticks` (SSE) and, with `--test-control`, `/api/test/{action}` for scripted tests. If the
  requested port is taken it binds an ephemeral port and logs it as an `http_listening` event.
- **Graphics-compat ladder:** chosen by `--compat-level N` or the persisted level file, and applied with
  `set_var` at the top of `main()`, before any thread or GTK init. The vars affect this process and its
  WebKit children only.

  | Level | Sets |
  |---|---|
  | 0 | nothing |
  | 1 | registers `tauri-plugin-wayland-nvidia-quirk` (early GL context) |
  | 2 | `WEBKIT_DISABLE_DMABUF_RENDERER=1` |
  | 3 | level 2 + `WEBKIT_DISABLE_COMPOSITING_MODE=1` |
  | 4 | `GDK_BACKEND=x11` |
  | 5 | browser fallback (no webview) |

- **Crash-loop detection:**
  1. Write `starting.json` before the webview is created.
  2. The page reports first paint through `invoke("first_paint")` after two `requestAnimationFrame`s, and the
     marker is deleted then.
  3. If the marker is still there at the next start (and its PID is dead), move one level up and persist it.
  4. Past level 4, fall back to the browser UI.

  `--reset-compat` clears this state, and `--no-first-paint-ack` simulates a window that never paints.

- **Test helpers (fixed after review P2):** `scripts/instance.sh STATE_DIR PID` reads the launched PID's own
  `http_listening` address and checks that `/api/state` answers with that PID. `api.sh` needs `S1_ADDR`. With
  `S1_PID` set, it re-checks the PID before every action and fails on HTTP errors. `matrix.sh` and
  `crashloop.sh` use only the discovered address; the fixed 47811 default is gone. Verified with a deliberate
  port collision ([port-collision.txt](S-1/rerun/port-collision.txt)): two instances asked for `--port 48200`,
  the second fell back to `:39389`, and `api.sh` aimed at 48200 with the second PID failed with "answers as
  pid A, not B". Without `S1_ADDR`, or on an HTTP 400, it exits 1.

Run it: `npm ci && npm run build && (cd src-tauri && cargo build --release)`, then
`scripts/launch.sh <abs-run-dir> -- --compat-level 1 --state-dir <abs-run-dir>/state --test-control`. Use
absolute paths: the app starts in Hyprland's cwd, not yours. `scripts/repro.sh`, `matrix.sh`, `crashloop.sh`,
`cycle.sh`, `tray.sh`, `gpu.sh` and `measure.py` reproduce the tables below. `repro-15-launches.jsonl`,
`fullscreen-anim.jsonl` and the `level` field in `gpu-per-process.jsonl` came from ad-hoc loops around the
same scripts (`launch.sh` + `wait-event.sh`; `api.sh fullscreen`/`animation` + `measure.py 15 5`); later
batches use `repro.sh`.

Reading the table:

- **Error 71 at level 0 comes from NVIDIA explicit sync** with WebKit's DMA-BUF renderer under Hyprland:
  turning off explicit sync alone removes it. Two other fixes also avoid it: the quirk, which sets up NVIDIA GL
  early in the UI process, and no-DMA-BUF, which doesn't share GPU buffers at all. Which protocol request
  Hyprland rejects was not traced (`WAYLAND_DEBUG` was not run).
- **The quirk is the cheapest fix:** it keeps WebKit on the GPU and needs well under half the fullscreen CPU of
  `__NV_DISABLE_EXPLICIT_SYNC` (12 % against 32 %; the difference is in the UI process). It also needs no env
  var.
- **No-DMA-BUF works but paints on the CPU.** It costs little for this simple page, but more for a busy
  designer canvas.
- **Level 4:** the session's `GDK_SCALE=2` takes effect under XWayland (`xwayland.force_zero_scaling`). WebKit
  asks NVIDIA GBM for a 2000×1400 buffer, that fails, and the window stays blank. The JS never acks, so the
  marker stays, but the process does **not** die: on its own the crash ladder only notices at the next start.
- The pre-reboot matrix is kept, unreferenced, in `spikes/S-1-tauri-shell/runs/matrix-pre-reboot-2026-10-18`
  (git-ignored). Don't use it.

## 4. Which GPU renders, and the broken-driver case

- With a healthy driver, **WebKit renders on NVIDIA**, the GPU that drives the displays, at levels 0+sync-off
  and 1. The AMD iGPU is not used. So E-1 **does** exercise the NVIDIA path that the field reports (research
  §4.1) describe, and reproduces their `Error 71`.
- The **early-GL quirk works as designed** when NVIDIA EGL works: the UI process holds NVIDIA fds and has no
  llvmpipe threads.
- **Broken driver state (userspace and kernel module mismatched, as in §0).** This is a real user scenario on
  rolling distros: upgrade, don't reboot. NVIDIA EGL fails, WebKit silently moves to the iGPU, and GTK GL lands
  on llvmpipe. The quirk then makes GTK paint every frame in software, which measured about 4.5 cores
  fullscreen in the first run. Level 0 happened to work then. The product must therefore:
  - detect the GL renderer GTK actually got, and treat `llvmpipe` (or `NVRM: API mismatch`) as "NVIDIA
    unavailable", which means don't apply the quirk;
  - offer a "restart your computer after the driver update" hint in the UI.

    visual and mouse check.**

- **Close-to-tray: ✅ for behaviour, ⚠️ for memory.**
  - Behaviour. Tray "Hide", a compositor close (`hl.dsp.window.close`, as with SUPER+W) and the page's button
    all destroy the window. The app stays in the tray. `engine.log` keeps ticking with `webviews=0`.

- **Quit** from the tray exits the app and all its WebKit children. No orphans were left after `SIGKILL`
  either (§8).

**Forced ladder (re-run after the reboot with the fixed `crashloop.sh`,
[forced-crashloop.txt](S-1/rerun/forced-crashloop.txt)).** Clean state, the script sent `SIGKILL` to the app 0.1 s
after launch, five times in a row. The level went 0 → 1 → 2 → 3 → 4 with no orphaned children, and start 6 came up
in **browser fallback**:

- no window and no WebKit processes;
- `GET /` returns 200 `text/html`, and `/api/state` reports `browser_fallback: true`;
- SSE delivered 3 ticks in 3 s, and the tray menu was still live;
- the same UI rendered in headless Chromium (first run, [browser-fallback-headless-chromium.png](S-1/browser-fallback-headless-chromium.png));
- the Host and Origin guard returned 403 for a foreign `Host` and for a cross-origin `POST`.

`crashloop.sh` now finds start 6's address through `instance.sh`. Other checks (first run): `--reset-compat` returns to
level 0, and `--no-first-paint-ack` (a window that never acks) bumps the level at the next start.

Gaps for production:

- **A live blank window is not caught** until the user quits (level 4 here). Add a first-paint watchdog: no ack
  within about 5 s means mark the failure, bump the level, and relaunch the UI or offer the browser.
- The JS ack proves the web process produced a frame, not that the compositor showed it. Keep tray "Open UI in
  browser" and a CLI flag as manual escapes.
- To survive a user's Ctrl+C during startup, bump only after **two** failures within N seconds (research §4.3),
  **except** for a detected hard crash (`Error 71` exit). Otherwise every NVIDIA user waits for two crashes.

## 10. Recommendation for ADR-0002

**Conditional GO: Tauri 2 stays the shell, but only with the compat ladder as a hard, tested requirement.**
Accept it after E-2 and E-3 confirm (DEN-20).

- **For.** With the right level, everything works on the owner's worst-case setup and renders on NVIDIA:
  about 350 ms first paint, 4 % CPU animated, 12 % fullscreen, under 0.5 % idle, and an 8.9 MB binary. The
  first-start crash recovers by itself (§8), and the browser fallback works.
- **Against.** Stock WebKitGTK 2.54 + NVIDIA 615 + Hyprland crashes on every launch at defaults, and level 4
  paints nothing. The app depends on an env/quirk ladder that tracks driver and WebKit releases, and a future
  driver can move the bug.
- **Why not switch now.** The failure is well understood and fully worked around in-process, so it doesn't
  justify Tauri 3 CEF (alpha, hundreds of MB) or Electron (more idle memory, and it fixes nothing else seen
  here). Both stay the exit hatch if E-2 or later drivers show failures that the ladder can't cover.

GO conditions (these replace the first report's conditions):

1. **NVIDIA-aware default.** On Wayland with an NVIDIA GPU, start at the early-GL quirk, after checking that
   NVIDIA EGL actually works (§4). Never ship level 0 as the NVIDIA default. Keep level 0 for other GPUs
   (untested here; E-2).
2. **Ladder:** quirk → `__NV_DISABLE_EXPLICIT_SYNC=1` → no-DMA-BUF → no-DMA-BUF + X11 → browser. Plain X11 is
   not a step (blank on NVIDIA). Bump immediately on a hard crash and after two failures otherwise.
3. **First-paint watchdog** so a live blank window also bumps the level (§8).
4. **Broken-driver detection:** if GTK's GL is llvmpipe or NVIDIA reports an API mismatch, skip the quirk and
   tell the user to reboot.

   on close. Don't promise always-on-top on Wayland; ship Hyprland/KWin rules and the OBS-dock chat.
6. Cap Tokio worker threads in the engine. Watch for `tray-icon` moving to libayatana-appindicator-glib.
